RFSAT Rover Configurator

RFSAT Rover Configurator

Builds the $SPSET command set for the RTK Everywhere RFSAT firmware: Wi-Fi networks, up to four NTRIP correction sources in priority order, Bluetooth and Galileo HAS fallback. Send it over USB from Chrome, or paste it into a Bluetooth terminal.

Wi-Fi networks

Tried in order. Up to four. Leave unused rows empty.

Correction sources

Source 1 has priority. On a failure (no connection, no response, rejected login or mount point, or 30 s without RTCM) the rover moves to the next source in about 2 s. Keep sources within 2–4 km of the work area for sub-centimetre fixes.

Receiver and Bluetooth

Profile file

Save the form as JSON to reuse it on the next unit. Passwords are included, so keep the file private. Nothing is stored in the browser.

Getting started: configure a rover in five steps

    
    
      
  1. Fill in your Wi-Fi networks (up to four, tried in order).
    2. 
      
  2. Fill in the correction sources: press a preset, then add the user and password your caster gave you. Source 1 is used first.
    3. 
      
  3. Check the receiver options. Keep Accuracy sentence for apps ticked if you use PocketGNSS or another app.
    4. 
      
  4. Press Save profile JSON so the same settings can be loaded for the next unit.
    5. 
      
  5. Send the commands: over USB with Connect USB then Send to rover, or over Bluetooth by copying them into a terminal (see the next topics). The rover saves them and restarts.
    6. 
    

    
Hover over any field or button to see what it does.

  


  
Entering command mode over Bluetooth +++ · nothing happens · reboot ignored

    
The rover accepts $SP… commands only in its command mode. Anything sent outside it is ignored, including $SPEXE,REBOOT. If the rover "does not react" or "does not reboot", it was not in command mode.

    
    
      
  1. Connect a Bluetooth terminal app (e.g. Serial Bluetooth Terminal) to the rover. Close PocketGNSS first: only one app can be connected.
    2. 
      
  2. Set the line ending to None (see the next topic).
    3. 
      
  3. Send nothing for 2 seconds, then send +++. Reply: Echoing all serial to BT device.
    4. 
      
  4. Send an empty line (Enter). The main menu appears.
    5. 
      
  5. Send +. Reply: COMMAND MODE; the stream of NMEA sentences stops.
    6. 
      
  6. Set the line ending to CR+LF and send the commands, one line at a time or pasted together.
    7. 
    

    
The commands this page generates already carry their checksum (*XX). If you type a command yourself, use the box under Rover replies: it adds the checksum for you. The terminal does not.

  


  
Setting the line ending in Serial Bluetooth Terminal

    
Menu ☰ → Settings → Send tab → Newline: choose None for +++ and +, and CR+LF for the $SP… commands. With None, the Enter step is done by pressing Send with an empty input field.

    
Other terminal apps have the same option, usually called "line ending", "newline" or "EOL".

  


  
The rover restarts when I connect USB or send a command

    
The Postcard's USB chip also drives the ESP32's reset and boot pins. Opening the USB port can restart the rover; you will see rst:0x1 (POWERON_RESET) and the start-up messages in Rover replies. A command sent while it starts is lost.

    
This page notices the restart, waits until the rover is running and sends again. If a send still fails, wait about 5 seconds after connecting and press the button again. Over Bluetooth this does not happen.

  


  
The messages scroll too fast to read the reply

    
Press Pause above Rover replies: the window stops moving while messages are still recorded, so you can select and copy text. Save to file stores the whole session in your Downloads folder.

    
In command mode the rover stops its NMEA stream, so its replies are easy to see there. Your own lines are shown with > in front.

  


  
Accuracy in the app differs from the rover's display

    
The display shows the LG290P's own estimated error ($PQTMEPE, 2D). By default the rover does not send that sentence over Bluetooth, so apps use GST, a different and usually larger statistic.

    
    
      
  1. Keep Accuracy sentence for apps ticked and send the commands, or send only $SPSET,messageRatePQTM_PQTMEPE,1*36, $SPEXE,SAVE*76 and $SPEXE,REBOOT*76 in command mode.
    2. 
      
  2. Check with EPE on? (reply 1).
    3. 
      
  3. In PocketGNSS, Live then shows a "Receiver error (H / down)" row. PocketGNSS 1.13.4 or later shows exactly the display's figure.
    4. 
    

    
The two update once a second, not at the same instant, so a short difference while the value changes is normal. A PocketGNSS recording includes accuracy.csv with both values at every second.

  


  
RTK Fixed drops to DGNSS or Float two correction streams

    
The most common cause is two correction streams reaching the receiver at once: the rover's own NTRIP client (over Wi-Fi) and a phone app relaying another caster over Bluetooth. Mixed RTCM from two bases breaks the RTK solution.

    
    
      
  • Use one source: either the rover's own client (this page) or the phone's relay, not both.
    • 
      
  • PocketGNSS 1.13.2 or later does this by itself: with a rover that has its own NTRIP client, the relay waits while the rover's corrections are in use and takes over only when they stop.
    • 
      
  • Other causes: a base too far away (keep it within a few km for centimetre fixes; for EUREF choose the nearest station), sky view blocked, or the caster stream interrupted. The rover moves to the next source after 30 s without RTCM when Failover is on.
    • 
    

  


  
Bluetooth: the phone's settings show "disconnected" or cannot connect

    
That is normal. The phone's Bluetooth settings can pair with the rover, but they do not open its data channel. The app does that.

    
    
      
  • Classic (SPP), Android: pair once in the phone settings, then connect from the app. The settings keep showing "disconnected" or "paired".
    • 
      
  • BLE (iOS, or Android apps that scan): do not pair in the settings. Find the rover with the app's scan and connect there. In PocketGNSS: Setup → Bluetooth LE → Scan → tap the rover → Connect; Live shows the position once data arrives.
    • 
      
  • If an earlier pairing gets in the way, unpair the rover in the phone settings and connect again from the app.
    • 
      
  • Only one app at a time can be connected to the rover.
    • 
    

  


  
Where is my profile JSON?

    
This page never saves anything by itself and keeps nothing in the browser. Press Save profile JSON: the file goes to your Downloads folder. Move it to a private folder and load it next time with Load profile JSON.

    
The file contains Wi-Fi and caster passwords: do not share it, e-mail it or commit it to GitHub.

  


  
Which firmware is on the rover?

    
    
      
  • The second boot screen shows the RFSAT release, e.g. v3.4-r4 96c1dc8 (release r4, commit 96c1dc8). A unit showing a lower release number needs updating; dev means a test build.
    • 
      
  • Or connect USB and press Firmware (the reply ends with the same RFSAT release) or LG290P version.
    • 
      
  • Or look at the top of the main menu: "RFSAT firmware v3.4-r4 … (built …)" (Enter over USB, or +++ then Enter over Bluetooth).
    • 
      
  • The ID in the top-left corner of the display (e.g. 7926) is the unit's Bluetooth ID, not a version.
    • 
    

  


  
What C: and M: on the display mean caster · mount point

    
From firmware r4, while the rover's own NTRIP client is connected, the rover screen shows the correction source in use: C: the caster (Metrica SmartNet, EUREF-IP, RTK2go by name; any other caster, e.g. your own base, by its address) and M: the mount point, e.g. MSM_VRS.

    
    
      
  • When the rover moves to another source (failover), the two rows change with it, so you can see which of your four sources is working.
    • 
      
  • The rows are empty while the client is connecting or has no source, and when corrections come from a phone app over Bluetooth: the rover does not know which caster the phone uses.
    • 
      
  • Names longer than 19 characters are cut.
    • 
    

  


  
Which firmware file goes on which unit?

    
File names end with the prototype ID: _V1 PicoRTK, _V2 ESP32-C6, _V3 Postcard with PostcardRTK, _V4 Postcard with this RTK Everywhere firmware. Never flash a file whose ID does not match the unit.

    
For V4: …_merged_V4.bin at address 0x0 for a first install (it erases the settings); …_V4.bin at 0x10000 to update and keep the settings.

  


  
Which correction source should I use?

    
    
      
  • Metrica VRS (MSM_VRS): a virtual base at your position; needs Send GGA position. Usually the best choice.
    • 
      
  • Metrica nearest (MSM_NEAR): the closest physical station.
    • 
      
  • EUREF: free with an account; choose the mount point of the nearest station (e.g. DYNG00GRC0 around Athens). A station 100 km or more away will rarely give a fixed solution.
    • 
      
  • Own base: your own base station, best when it is within a few km.
    • 
    

    
Put the source you trust most first; the rover returns to source 1 after the Return to source 1 time.

  


  
USB does not work at all

    
    
      
  • Use Chrome or Edge on a computer; Firefox and Safari do not support USB serial.
    • 
      
  • Open this file from your disk (or from its published page). The USB port picker lists the rover as a CH342 / USB serial device; the Postcard shows two ports: try the first, then the other.
    • 
      
  • Close other programs using the port (Arduino IDE, a terminal, the flasher).
    • 
      
  • Use a USB data cable, not a charge-only one.
    •
